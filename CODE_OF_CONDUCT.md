# Code of Conduct

## The short version

Be decent to people. Assume good faith. Keep criticism about the code, not the person.
Everyone here is doing this in their spare time.

## What's expected

- Be welcoming to people at any experience level. "How do I set up SSH keys?" is a fine
  question in a project about home hardware.
- Give feedback on the work, with reasons. "This adds a dependency, which the project
  rules out — here's why" helps; "this is bad" doesn't.
- Accept that a well-made contribution can still be declined on principle. The
  [zero-dependency rule](CONTRIBUTING.md#the-one-rule-zero-dependencies) is not a
  judgement of your code.
- Respect that maintainers reply when they can.

## What isn't

Harassment, insults, or demeaning comments. Sexualised language or imagery. Personal or
political attacks. Publishing someone's private information. Sustained disruption of
discussions. Anything else that would make a reasonable person not want to participate.

This applies in issues, pull requests, commit messages, code comments and any other
project space.

## Enforcement

Report a problem to the repository maintainers via GitHub — privately, if you'd rather.
Reports are handled discreetly, and you won't be named without your agreement.

Responses range from a private word to editing or removing content, to a temporary or
permanent ban from the project. Maintainers apply this in good faith and proportionately.
